# Cyber Neon デザインガイド（fragbase） - Draft v1

最終更新: 2025-11-17

## 1. プロダクトコンセプト

- fragbase は「ゲームに関わるノウハウや記録など何でも投稿できる、ゲーマーのためのコミュニティプラットフォーム」。
- 世界観のキーワード:
  - ゲーマー向けネオン世界観
  - 「ネオン研究所」「Game Notes Terminal」「Cyber Research Base for Gamers」
  - 情報（ノート・データ）がホログラムとして立ち上がるラボ
- トーン:
  - クール・スマート寄り
  - 「大会ロビー」ほど騒がしくなく、「静かなハイテクラボ」で落ち着いて読み書きできる場所

---

## 2. ビジュアルコンセプト（Cyber Neon）

### 2.1 全体方針

- 情報（ノート）を読む・書く体験が主役。
- 背景は静かでダーク、文字と余白で読みやすさを確保。
- ネオンは「アクション」「重要情報」「ラボ感の演出」に限定して使う。
- 1画面につき「強いネオン」は 1〜2 色まで（基本はメインアクセントだけで回す）。

### 2.2 ベースカラーパレット（ドラフト）

※後で Tailwind のカラートークンに落とし込み予定の概念名を併記。

- 背景
  - `#03040A` — アプリ全体のベース背景（`bg.base`）
  - `#06081A` — カードやモーダルなどの面（`bg.surface`）
  - `#0A0E24` — ナビ・フッターなどの少し持ち上げた面（`bg.elevated`）
- テキスト
  - `#F5F7FF` — メイン本文・見出し（`text.primary`）
  - `#A0A4C0` — サブ情報・メタ情報（`text.muted`）
  - `#62657F` — プレースホルダー・ごく薄い補足（`text.subtle`）
- アクセント（ネオン）
  - `#00F5FF` — メインアクセント（リンク・Primary ボタン・選択状態）（`accent.primary`）
  - `#FF3BFE` — サブアクセント（通知バッジ・特別なタグ）（`accent.secondary`）
  - `#7BFF4A` — 成功・達成・ポジティブ指標（`accent.success`）
- ボーダー / アウトライン
  - `rgba(255, 255, 255, 0.04)` — 通常のカード境界線（`border.subtle`）
  - `rgba(0, 245, 255, 0.5)` — ネオンアウトライン・フォーカス（`border.neon`）

### 2.3 デザイントークンの実装場所（約束事）

- 色・トーンを変えたいときに触るファイルは基本的に 2 つ:
  - `app/globals.css`
    - `--background`, `--foreground`, `--card`, `--accent` などの CSS 変数を定義。
    - Cyber Neon のカラーパレットに合わせて、ここを変更すれば全体テーマが切り替わるようにする。
  - `tailwind.config.js`
    - 上記の CSS 変数を `background`, `foreground`, `primary`, `accent`, `card` などの Tailwind カラーにマップ。
- コンポーネント / ページでは、基本的に以下のような「意味ベース」のクラスだけを使う想定:
  - 例: `bg-background`, `bg-card`, `text-foreground`, `text-muted`, `border-border`, `bg-accent`, `bg-primary` など。
- hex や rgb を直接コンポーネントに書かない方針にし、「テーマ変更 = `globals.css` の変数更新」で完結させる。

## 3. コンポーネント別ルール（見た目の方向性）

※このセクションは「どういうニュアンスにしたいか」のガイドです。実装は後続タスクで調整。

### 3.1 ヘッダー / ナビゲーション

- 背景: `bg.elevated`（#0A0E24）。
- 下辺に 1px の弱いネオンライン（`accent.primary` を低めの不透明度で）。
- アクティブリンク:
  - テキスト: `accent.primary`
  - 下線または小さなピル（pill）で状態を示す。
- 非アクティブリンク:
  - 通常: `text.muted`
  - ホバー時: `text.primary` + ごく弱いグロー。

### 3.2 ノートカード（フィード）

- 背景: `bg.surface`。
- ボーダー: `border.subtle` の 1px。
- 左端に 2px の縦ネオンライン:
  - 可能ならゲームごとに色分け、なければ `accent.primary`。
- 内容:
  - タイトル: `text.primary`
  - メタ情報（ゲーム名 / 投稿日 / 著者など）: `text.muted`
- ホバー:
  - ボーダー色をわずかに明るく（`border.neon` を弱めたトーン）。
  - ほんの少しだけシャドウ/グローを追加（位置はほぼ固定）。

### 3.3 ノート詳細（記事ページ）

- 本文領域の背景はフラット寄り（`bg.surface`、グローなし〜ごく弱く）。
- 見出し:
  - H2/H3 に左側の細いネオンラインまたは下線でラボのセクション感を出す。
- 引用ブロック:
  - 背景を `rgba(255, 255, 255, 0.02)` ほどでわずかに持ち上げる。
- 長文の読みやすさを最優先し、ネオン演出は控えめに。

### 3.4 ボタン

- Primary ボタン（例: 投稿ボタン）
  - 背景: `accent.primary`
  - テキスト: `bg.base`（ほぼ黒）
  - ホバー: わずかなアウトライングロー + 明度を少し上げる。
  - 1 画面に 1〜2 個まで（メインアクションのみ）。
- Secondary ボタン（例: キャンセル、サブアクション）
  - 背景: `bg.surface`
  - ボーダー: `border.subtle`
  - テキスト: `text.primary`
  - ホバー: ボーダーを `accent.primary` 寄りにして存在感を出す。
- Ghost / Text ボタン（例: フィルタ、タブ）
  - 背景: なし
  - 通常: テキスト `text.muted`
  - ホバー: テキスト `accent.primary`
  - 選択中: 下線または下辺 2px ネオン。

### 3.5 タグ / バッジ

- ゲームタグ:
  - 背景: `accent.primary` の 10〜15% 不透明度。
  - テキスト: `accent.primary`。
- ステータス（攻略中 / 完了 など）
  - 完了: `accent.success` 系。
  - 注意喚起: 暖色アクセント（例: `#FFB347`）を少量。
- 通知バッジ:
  - 未読数などは `accent.secondary` を使い、使用箇所を絞る。

### 3.6 フォーム / エディタ

- 入力フィールド:
  - 背景: `bg.surface`
  - ボーダー: `border.subtle`
- フォーカス時:
  - ボーダー: `border.neon`
  - ごく薄いアウトライングロー（ネオン過多にならない程度に）。
- プレースホルダー:
  - テキスト: `text.subtle`
- エディタヘッダー:
  - タイトル・公開設定などを HUD 風に細い区切り線で分割。

## 4. タイポグラフィ

### 4.1 基本方針

- サンセリフ系フォントで、読みやすさ優先。
- 英字の短いラベル（CTA ボタン、タグなど）は大文字またはスモールキャップ風にして HUD 感を出す。

### 4.2 情報階層のイメージ

- H1（ページタイトル）
  - 太字・大きめサイズ
  - カラー: `text.primary`
- H2（ページ内セクションタイトル）
  - H1 より一段小さく
  - 左側にネオンラインまたは下線
- H3（カード内タイトルなど）
  - 太字だが控えめなサイズ
  - 情報密度がある印象になるよう行間はやや詰める。
- Body（本文）
  - 行間はゆったり（1.6 前後）で長文を読みやすく。
  - カラー: 基本 `text.primary`、補足・メタ情報は `text.muted`。

## 5. アニメーション / インタラクション

### 5.1 時間とイージング

- ホバー:
  - 150–200ms 程度
- モーダルやページ単位のトランジション:
  - 200–250ms 程度
- イージング:
  - 基本 `ease-out` をベースに、表示はなめらか・応答はキビキビ。

### 5.2 挙動の方向性

- ホバー:
  - 明度とグローが少し増える。
  - 位置やサイズは大きく動かさない（落ち着いた印象優先）。
- クリック時:
  - 一瞬だけ縮む、またはグローが抑えられるなどの軽いフィードバック。
- ローディング:
  - 細い横ラインが流れる / ネオンリングがほんのりパルスするなど、HUD 的な演出。

## 6. 実装タスク一覧（まだ実装しない前提）

以下は「このガイドをもとに実際の UI を変更する」ためのタスク案です。  
順番に進めながら、各ステップでフィードバックをもらう想定です。

### フェーズ 0: デザインガイドの確定

1. このファイルの内容（コンセプト / カラー / コンポーネント方針）をレビューして微調整。
2. 不足している画面種別があれば追記（例: モーダル、ダッシュボード的ビューなど）。

### フェーズ 1: デザイントークンの整備

1. `app/globals.css` の CSS 変数（`--background`, `--card`, `--accent` など）を、Cyber Neon カラーパレットに沿う形に更新する（※この段階では実際の値を差し替えるかどうかは別途相談）。
2. `tailwind.config.js` の `theme.extend.colors` が、上記 CSS 変数を参照していることを確認し、必要であれば命名を調整（`background`, `foreground`, `primary`, `accent`, `card` など）。
2. 既存の色クラスから、共通トークンに置き換えやすいマッピングを整理（どの画面で何色が使われているか軽く棚卸し）。
3. テキストスタイル（H1/H2/H3/Body）のスケールとクラスセットを定義（ユーティリティ or `components` レベル）。将来的にフォントサイズや太さを変えたくなった際に 1 箇所で調整できるようにする。

### フェーズ 2: 共通レイアウト / シェルの更新

1. ヘッダー / フッター / メインレイアウトの背景色・ボーダー・タイポグラフィをトークンベースに統一。
2. ナビゲーションのアクティブ / ホバー状態を、`accent.primary` ベースのスタイルに変更。
3. 全体のパディング・コンテナ幅などを軽く調整し、ラボ感のある余白感に揃える。

### フェーズ 3: キーコンポーネントのリデザイン

1. ノートカード（フィード）のスタイルを、ここで定義したルールに沿ってリデザイン。
2. ノート詳細ページの見出し・本文・引用ブロックをダークモードでも読みやすい形に整える。
3. Primary / Secondary / Ghost ボタンのコンポーネントを整理し、全体で統一。
4. タグ / バッジのスタイル（ゲームタグ、ステータス、通知）を共通化。

### フェーズ 4: エディタ / フォームのアップデート

1. 投稿エディタのヘッダー（タイトル・公開設定など）に HUD 感のある区切り線・背景を導入。
2. 入力フィールドのフォーカス状態を `border.neon` ベースに統一。
3. バリデーションエラーやヘルプテキストのスタイルを整理（色・アイコン・配置）。

### フェーズ 5: アニメーション / 微調整

1. ホバー / フォーカス / クリック時のトランジション統一（時間・イージングを共通化）。
2. ローディングインジケーターやスケルトンの見た目を、Cyber Neon 世界観に合わせて調整。
3. モバイル / タブレット時の挙動（タップ時のフィードバックや余白）を確認・調整。

### フェーズ 6: QA と微修正

1. 主要画面（ホーム / ノート詳細 / プロフィール / 投稿エディタ）を一通り確認し、可読性とネオンのバランスをチェック。
2. コントラスト比とアクセシビリティ（AA 目安）を簡易チェック。
3. 必要に応じて、このガイドと実装差分を反映してアップデート。
